## Pen and coexistence research boundary (historical, 2026-10-19)

Microsoft's [required pen top-level collections](https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/required-hid-top-level-collections) and [touch and pen support](https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/touch-and-pen-support) require **separate** Digitizers/Touch Screen (0x0D/0x04) and Digitizers/Pen (0x0D/0x02) Application collections for Windows touch and `POINTER_PEN`. A Report ID alone cannot register a Pen collection. **At this early research stage**, `PictureActivity` already mapped stylus/eraser pressure, hover and buttons to `UibcPenContact`, but the channel serialized Pen ID 2 while the then-verified type-2 descriptor advertised only Touch ID 1. The experimental type-3 descriptor added a Pen ID 2 TLC and Contact Count Maximum Feature ID 3. Pen flags followed the Microsoft sample (Tip bit 0, Barrel 1, Invert 2, Eraser 3, padding 4, In Range 5, padding 6–7), with picture-pixel X/Y and 16-bit pressure. Windows pen/coexistence had **not yet been observed at that stage**. These are historical findings, **not the delivered implementation**: final type 2 uses Touch IDs **1–10** and Pen ID **11**, with live Windows gates verified in runs **86/87**. Physical S Pen remains unverified. The source advertised `SingleTouch/USB, MultiTouch/USB` (Generic `none`); WFD v2.1 supplies no separate pen HID type. Android writes and a unit-tested TLC alone are still not evidence of Windows pen support.

## Interpretation and release boundary

Microsoft's [Windows multitouch usages](https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/supporting-usages-in-multitouch-digitizer-drivers-win8) require Contact ID, Scan Time, and **Contact Count Maximum in a feature report in the touch top-level collection**: "A device without the Contact count maximum in the descriptor will be considered to be a single-touch device." Microsoft's [sample touchscreen descriptor](https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/touchscreen-sample-report-descriptors) shows a two-finger parallel report with a distinct maximum-feature report ID. [Wi-Fi Display Technical Specification v2.1](https://tools.barco.com/kb-downloads/4814/Wi-Fi_Display_Technical_Specification_v2.pdf) §4.11.3.2, page 69, defines HIDC type 2 = Single Touch, type 3 = Multi Touch, and Usage 0x00 = input report / 0x01 = report descriptor; it does **not** specify a network `GET_FEATURE` request or feature response. [VHF documentation](https://learn.microsoft.com/en-us/windows-hardware/drivers/hid/virtual-hid-framework--vhf-) says the *local* HID source driver must handle GetFeature or VHF responds `STATUS_NOT_SUPPORTED`. Neither these logs nor the network protocol establish what callback this Windows Miracast source implements; adding an Android socket reader for an unspecified network request is not justified.

The early two-contact Feature/Pen candidate passed **223/223** unit tests and both APK builds, but failed the valid Windows pen/two-finger probes in runs 46/47. A disable-release loopback regression first failed with `SocketTimeoutException`, then passed after moving releases ahead of disable; that failure evidence remains archived. Those early green tests did not establish Windows support. Type-3 input stalling remains an unresolved diagnostic finding, not a prerequisite for the subsequently demonstrated type-2 route.

The current implementation uses **one type-2 socket**, ten independent single-touch TLCs (Report IDs 1–10), and one Pen TLC (ID 11), totaling **1452B**. Each touch TLC preserves the original 135B layout apart from its report ID. Packet builders and channel agree with caller slots 0–9; type-3 packed/maximum-report experiments and the second-socket method remain diagnostics only. Full current regression XML contains **16 suites / 230 tests / zero failures, errors, or skips** (26 packet tests, 11 channel tests), including disable/release, high-slot delivery, report layout, type switching, and repeated pen tip/hover/idle samples. Both APK builds pass.
