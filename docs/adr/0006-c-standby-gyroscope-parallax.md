# ADR 0006: C 待機主題以前後景共同視差保留內容可讀性

狀態：接受（Prototype）；網頁已接入裝置方向感測，Android 原生感測器整合尚未實作。

依使用者新版要求，本決策取代先前「只有粒子背景傾斜、前景不動」的限制：只有 C 主題的粒子背景、品牌、左下連線提示、右下狀態時鐘與 HUD 接收同一方向輸入，以獨立移動狀態表現遠近。原型評分、設定與導航不做視差，以免影響操作；不移動包含這些控制項的整頁根節點。v20 改為分層純平移，取消透視、旋轉與動態縮放，避免反向一側局部放大；HUD 的獨立橢圓晃動另以實際可用空間限幅，不把兩種動態混為同一個百分比。

## Prototype 邊界

- 滑鼠四方向移動只模擬陀螺儀輸入，以待機可見區域中心為原點，右／下為正，輸入直接依視口正規化為 `[-1, 1]`，不再加上八倍中心增益。v23 在合格 C 頁面預設接入真實 `DeviceOrientationEvent` 融合姿態；它不是原始陀螺儀讀值，也不代表 Android 原生應用已接入感測器。感測器啟用期間滑鼠不得覆寫姿態。
- `window.MiraxCParallax` 分別更新粒子 canvas 與邊角資訊圖層，兩層不得互相巢狀繼承視差變換；只作用於上述 C 視覺元素，不改變控制項的層級或命中範圍。裝飾圖層保持 `pointer-events: none`，不新增遮擋操作的 overlay 或依賴。
- `setPointer(x, y)` 只更新目標；`update(deltaSeconds)` 由現有 `animateStandby` 驅動，不另啟 rAF 或監聽事件。v21 粒子使用每秒係數 4、邊角資訊使用每秒係數 2 的指數平滑，各自保留 x／y 移動歷史；標題跟隨與停止後的收斂皆較慢，不再只是把粒子位移乘固定比例。單次步長最多 0.1 秒，避免恢復頁面時跳動。
- 前後景只以 `translate3d(x, y, 0)` 分層平移，不使用 `perspective`、`rotateX/Y` 或 `scale`，各處尺寸與方向一致，不產生局部透視放大。背景平移上限為視口短邊的 `1.89%`，邊角資訊為 `1%`，粒子與資訊維持獨立速度，保留深度差與內容可讀性；不因背景留邊尺寸改變位移增益。
- 前景不放大；品牌、連線提示、狀態時鐘與整組 HUD 在視口內安全內縮，按最不利的平移視差、HUD 晃動及 OLED 位移合成結果預留邊界。不得裁字、互相壓住重要資訊，或遮住一般操作；空間不足時縮小動態幅度，不靠裁切或放大文字解決。
- C 對話框依新版要求改為小橢圓循環，不再產生隨機路徑。使用現有 `animateStandby` 的 rAF，以 `x = radiusX × cos(angle)`、`y = radiusY × sin(angle)` 計算，每 5.5 秒一圈；水平半徑最多 `6px`、垂直半徑最多 `3px`，窄視口按安全空間限幅。錨點、引線與對話框一起移動；每則訊息的出現位置與內容仍沿用原有刷新，不把它們混作晃動路徑。不另開 rAF、CSS 或 WAAPI 晃動動畫，不加速 OLED 漫移。
- 沿用透明 canvas 與既有裁切規則；以視口短邊 `2%` 向外取整的實際繪圖緩衝邊界覆蓋最大平移，不放大背景。Canvas CSS 尺寸、像素緩衝區與繪圖原點一起更新，粒子位置與 X 幾何仍使用原視口尺寸。不新增遮罩或黑底，不以移動前景來遮掩背景邊界。

## 歸中與整合責任

`reset()` 同步清空目標、兩層各自的平滑歷史及所有前後景視差變換。宿主在滑鼠離開、視窗失焦、頁面隱藏、有效減少動態、暫停、離開 C 主題、離開大待機首頁、改用自訂背景或進入投放時立即呼叫；恢復後等待新的滑鼠輸入；已啟用的感測器清除前次移動樣本，等待新資料，不記住啟動中立姿態。縮放或版面尺寸變更也先歸中。暫停、有效減少動態與投放時，HUD 橢圓晃動也停止並歸中，不停在偏移姿態。

是否允許視差必須同時檢查 C 主題、大待機首頁、非投放、沒有自訂背景、頁面可見、未暫停及未啟用有效減少動態。不可只依賴 OLED 位移的啟用條件，因 OLED 防烙印位移可能在減少動態時仍需運作。既有 OLED 隨機漫移仍獨立，幅度、速度與節奏不隨本次視差或對話框增幅而改變，也不與前後景視差共用同一個 transform 寫入點。

使用者回報顯示 `motion.reduced: true`，且 `gyroscope.enabled: false`／`status: idle`；依相同手機視口與系統偏好可重現 HUD 位移為零、陀螺儀按鈕停用。這是動態偏好閘門，不是幅度不足或已證實的 HTTPS 失敗。

依使用者最新明確要求，C 原型的對話框與視差預設開啟，即使系統要求減少動態亦然；設定清楚顯示已勾選的「僅此原型允許晃動」，可以取消允許或暫停。v23 改為預設啟用感測器意圖，不改手機設定、不持久化。`motion.reduced` 保留系統原值，`motion.effectiveReduced` 回報 C 預覽選擇後的值。系統偏好變更保留勾選／取消選擇，重新整理回到 C 預設開啟；若瀏覽器需要手勢授權，仍須明確操作，不能繞過權限。取消允許、暫停、失焦、投放等仍須立即歸零並停止感測器。其他主題及 ERROR 震動仍沿用系統偏好，不因 C 原型設定而放寬。

## 網頁感測器與 HTTPS

- v23 宿主於首次符合 C 動態條件時嘗試自動啟用一次；不需要手勢權限的平台直接訂閱。手動停止、拒絕或逾時後，render／focus／切換主題不再自動重試；重新整理恢復預設意圖，其他主題不自動啟用。若瀏覽器提供 `DeviceOrientationEvent.requestPermission()`，在該次使用者操作內直接呼叫；獲准後仍須收到第一筆有限且範圍合法的 `alpha`、`beta`、`gamma` 才顯示已啟用。預設啟用不能自動呼叫此授權方法；載入時保留啟用按鈕，等待使用者點擊。沒有此權限方法時直接訂閱資料，不誤判為不支援。
- 依 W3C 的 Z-X-Y 次序建立旋轉矩陣，使用 `transpose(R_previous) × R_current` 及實際取樣間隔求當下左右／上下角速度，不再保存啟動時的固定中心。首筆只接續移動歷史；同側姿態向反方向移動也須立即反向，相同姿態輸入為零。`90°/s` 對應最大正規化輸入，`30°/s` 為 `1/3`，降低速度增益；150ms 無新有效樣本送零目標，由 `MiraxCParallax` 平滑收斂，不瞬間跳位或宣稱硬體故障。非正間隔忽略，間隔超過250ms先接續新樣本並輸入零，避免恢復時尖峰。
- 依 `screen.orientation.angle` 對應 0／90／180／270 度，舊瀏覽器才回退至 `window.orientation`；螢幕旋轉與版面尺寸變更透過 `resetMotion()` 清除舊樣本歷史；不提供沒有意義的「重新置中」按鈕。初始等待三秒沒有完整資料即回報未收到資料、解除訂閱，不能宣稱硬體不存在；已啟用且靜止沒有新事件不算故障。
- 失焦、隱藏、暫停、有效減少動態、離開 C、大待機或進入投放／自訂背景都停止讀取、清 timeout 與移動歷史並歸零。恢復時只重訂閱已獲准且仍有啟用意圖的感測器，不重彈權限。停止可使尚未完成的權限請求失效，晚到的獲准結果不得重新啟動。資料僅在本頁記憶體計算，不持久化或上傳。
- 非 loopback 的 `http://100.x.x.x` 不是安全環境，即使傳輸經 Tailscale 加密也不能取得感測器。預覽以 Tailscale Serve 的獨立 HTTPS 埠反代到 loopback 後端；保留原有其他服務，不使用 Funnel、不忽略憑證。使用者裝置須在允許存取的 tailnet 內。
- 評價 API 保持相對同源路徑。伺服器以單一 `--public-origin https://<machine>.<tailnet>.ts.net:8443` 明確指定外部原點，只有 loopback 代理且 Origin 精確相符才能進入此 HTTPS 寫入分支；仍拒絕 cross-site，不信任客戶端的 forwarded headers，不放寬 CORS。既有 HTTP 本機分支及嚴格資料驗證保留。

來源：[W3C Device Orientation](https://www.w3.org/TR/orientation-event/)、[MDN requestPermission](https://developer.mozilla.org/en-US/docs/Web/API/DeviceOrientationEvent/requestPermission_static)、[W3C Secure Contexts](https://www.w3.org/TR/secure-contexts/#is-origin-trustworthy)、[Tailscale Serve](https://tailscale.com/docs/reference/tailscale-cli/serve)。

## Android 後續

Android 未來由裝置 orientation／gyroscope 提供同樣的正規化輸入，由當下移動方向與速率正規化後沿用此效果預算，不使用固定啟動中心；感測器不可用、資料無效或使用者減少動態時，fallback 為中立靜態背景，不要求額外操作。此 ADR 不實作 Android 感測器、權限或生命週期接線。

此裝飾性視差不旋轉投放畫面、不改變一般觸控座標，也不取代 [ADR 0005](0005-projection-orientation-lock.md) 的投放期間鎖定轉向。

## 回歸驗證

`node design/big-standby-motion-prototype/verify-c-parallax.cjs` 驗證四方向、輸入與時間邊界、無 NaN、粒子每秒係數 4／標題每秒係數 2 的跨幀率平滑、獨立速度／反向／收斂、兩層立即歸中、純平移語法、背景 `1.89%` 與邊角資訊 `1%` 的上限。`verify-c-parallax-ui.js` 驗證各方向的文字尺寸不變、緩衝畫布覆蓋邊界且沒有縮放繪圖，以及一般滑鼠移動 80px／50px 在 1440×1000 視口僅造成 0.5px 至 5px 的輕微前景位移。另需驗證評分／設定／導航不受視差影響、HUD 橢圓晃動與 OLED 漫移互相獨立，及暫停／減少動態／投放時歸中。這些是數學與介面的回歸要求，不代表實體裝置的感測延遲或觀感已驗收。

窄視口與最大合成姿態仍需視覺確認文字、HUD 錨點與引線不出界、不遮住重要資訊或一般操作。小字與半透明文字在晃動中更難閱讀；若安全內縮仍不足，優先降低對話框晃動與前景深度。數學測試不冒充裝置或視覺驗收，本 ADR 不宣稱已完成這些驗收。

感測器另以 `verify-c-gyroscope.cjs` 驗證權限競態、失敗回退、同側反向、16／33／100ms 下 `30°/s → 1/3` 與 `90°/s → 1`、idle 歸零、四方向／旋轉映射與直立姿態；`verify-c-gyroscope-ui.js` 驗證啟用／停止、歷史重設、宿主生命週期與感測輸入至 DOM 實際產生的兩層不同反應速率，`verify-c-gyroscope-https.js` 另以冷 HTTPS 載入與瀏覽器原生方向事件模擬驗證整合，要求所有 script 成功載入，不容許反代突發連線造成 502。`verify-c-reduced-motion-ui.js` 另以手機視口與系統減少動態，覆蓋 C 預設開啟、小橢圓方程與實際位移、明確感測器啟用、取消允許、暫停、跨主題、系統偏好變更保留選擇，以及重新整理回到預設動態／感測器意圖，需手勢授權的平台仍等待點擊。`verify-c-auto-gyroscope-ui.js` 另覆蓋免提示平台自動訂閱、手動停止不被覆寫、暫停恢復、其他主題與進入 C 的邊界。這些測試清楚區別模擬事件、瀏覽器感測器模擬及實體裝置證據。HTTPS 原點與拒絕寫入由隔離 JSON fixture 的後端測試覆蓋，不以真實評價檔做寫入測試。
