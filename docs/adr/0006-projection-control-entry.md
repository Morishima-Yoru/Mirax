# ADR 0006: 投放控制面板使用明確入口

狀態：接受。取代以返回鍵開啟投放控制面板及連按返回結束連線的操作；ADR 0005 的轉向鎖定決定不變。

## 背景

一般觸控實現後，返回滑動會和 Windows 畫面邊緣的操作衝突。等比畫面沒有覆蓋的區域也曾因播放背景的點擊事件而打開控制面板，造成誤觸。

## 決定

- 提供投放畫面內的半透明邊緣把手，以及長按任一音量鍵兩種入口；在 Advanced 的「投放面板入口」中二選一，預設把手。選擇持久保存，舊設定缺少此值或值無效時也採把手。不新增懸浮窗權限或全域按鍵攔截。
- 只啟用選中的入口：把手模式不攔截音量鍵；音量鍵模式不顯示把手。這與離開投放後回到畫面用的懸浮球設定無關。
- 把手初始吸附右上邊緣，距頂部 72dp；外觀寬 8dp、高 56dp，半透明。保留 48×56dp 的無障礙觸控區，不擴大成全高邊緣感應區。拖曳以按下時的抓取點一比一追蹤手指，不做延遲平滑；放開後以 180ms 減速動畫吸附較近的左右邊緣，條帶在觸控區內同步過渡，不在換邊時瞬移 40dp。拖移不開啟面板。位置僅保留於目前的投放 Activity，不新增持久偏好。
- 吸附側不畫描邊，只有內側及上下圓角保留抗鋸齒輪廓；按下及拖移時也維持半透明。把手位於除錯疊層之上，完整控制面板仍在最上層。
- 把手移動的可見性必須用整個螢幕的合成截圖驗證，不能只看 `isShown`、View 邊界、點擊成功或 `View.draw()`。SurfaceView 的視窗透明區域若停在舊位置，即使上述檢查全通過，合成器仍會裁掉移動後的控制項。
- 把手與除錯疊層放在固定全視口的手機控制項繪製層。繪製層本身不移動，SurfaceFlinger 在拖曳前就保留固定合成區域；拖曳、吸附動畫不再逐幀請求 layout／透明區域重算，避免畫面位移與裁切區域不同步。這會增加全視口的透明混合成本，但不遮住影片、不改解碼路徑，也不把全視口變成觸控區；未命中子控制項的接觸仍落到影片 SurfaceView。
- 把手的按下、拖曳、吸附、閒置是明確狀態。取消或加入第二指會撤銷此手勢並返回按下前的停靠側／高度；不把接觸轉交其他手指。重新按下會接手動畫當下的位置，不重設抓取點。隱藏、移除或視口變更時清除舊接觸與動畫。
- 點擊資格必須檢查整次接觸的批次歷史樣本與放開樣本，不能只檢查每次 MOVE 的最後一點；一旦超過拖曳容差，即使移回按下處或已被螢幕邊界夾住，也不能再恢復點擊資格。Android 的 `FLAG_CANCELED` 放開事件視同取消，不開啟面板。真正的邊緣短按與無障礙點擊仍可開啟面板。
- 拖曳邊界以可見 8dp 條帶計算，不以其內側 40dp 透明觸控留白限制移動；手指拉向另一側螢幕邊緣時，條帶可以跟到邊緣，不會停在離手指 40dp 的地方。吸附完成後恢復完整 48dp 螢幕內觸控區。
- 這只改變收合入口，點擊後仍展開完整的投放控制面板，不縮小面板內的控制項。
- 短按音量鍵調整投放使用的媒體音量；長按只開啟面板，一次按住只觸發一次，不調整音量。面板已開啟時不反向收合。
- 畫面以外的背景接觸不開啟面板，也不轉送到 Windows。畫面上的多指接觸不挪作手機手勢。
- 返回只離開面板的二級頁或關閉面板；面板關閉時不動作。結束連線仍須使用面板的結束按鈕並確認。
- 把手與除錯疊層都屬於手機控制項；滑入或被控制項覆蓋的 Windows 接觸須結束，不能在同一次按住期間復活。面板開啟時結束全部接觸。
- 投放沉浸模式申請返回手勢排除；面板開啟時恢復返回操作。不攔截 Home／多工逃生操作，不以移除返回回呼冒充系統手勢已停用。

## 後果

- 把手會占用一小塊畫面，但可移開；音量鍵入口不占用畫面。把手內側的透明觸控區仍歸手機，不歸 Windows。選用音量鍵入口時，長按不再連續調整音量，短按在放開時生效；把手模式保留原本系統音量鍵行為。
- 若裝置韌體攔截音量鍵長按，仍可經 Home 回到 Mirax 的 Advanced 改回把手，不依賴面板本身才能切換入口。
- Android 的手勢排除有平台限制，OEM 韌體也可能不同；測試裝置通過不等於 Samsung Fold 全邊緣觸控已驗收。
- 不要求系統新增特殊權限、不使用三指等手勢，避免占用正式支援的十指輸入。
- [釘選實測](../research/screen-pinning-feasibility.md)只改善部分系統干擾；頂部仍會漏接接觸，不把釘選當成完整的上下邊緣觸控解法，也不自動鎖定裝置。
- 系統狀態列／多工仍可從保留手勢叫出；這項需求尚未解決。全螢幕、左右返回排除和把手修正，都不代表已禁止 Android 的上下系統手勢。
- 後續交付依使用者決定先修把手，不加入自動釘選、全機禁用旗標或縮小投放視口的替代方案；上下系統手勢問題另行處理。

## 平台依據

[`View.setSystemGestureExclusionRects`](https://developer.android.com/reference/android/view/View#setSystemGestureExclusionRects(java.util.List%3Candroid.graphics.Rect%3E)) 的一般上限為每側 200dp 垂直長度；以 sticky 方式隱藏導覽列時不受此限。現有 `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE` 配合隱藏導覽列符合 [AOSP 的例外條件](https://android.googlesource.com/platform/frameworks/base/+/152d0e6%5E%21/)。這不排除 [mandatory system gestures](https://developer.android.com/reference/android/view/WindowInsets#getMandatorySystemGestureInsets())，也不保證其他廠商韌體行為一致。
